# TiDB Initial Database Schema

This document outlines the initial tables and schema planned for execution in the 
ihongo_master database, as generated by Drizzle ORM.

## Planned Tables

1. **users**
   - Core table for authentication and user profiles.
   - Columns: id (UUID), email, username, password_hash, 
ative_language, current_level, vatar_url, vatar_id, xp_points, streak_days, google_id, created_at, updated_at.
2. **srs_cards**
   - Spaced Repetition System logic.
   - Columns: id, user_id, card_type, card_ref_id, ease_factor, interval_days, epetitions, 
ext_review_date, last_review_date, is_mastered, created_at.
3. **user_badges**
   - Badges earned by the user.
   - Columns: id, user_id, adge_type, adge_name, warded_at.
4. **user_kanji_progress**
   - Kanji learning progress.
   - Columns: user_id, kanji_id, ecognition_level, mastered, eview_count, last_reviewed_at, created_at.
5. **user_lesson_progress**
   - Lesson completion status.
   - Columns: user_id, lesson_id, status, score, 	ime_spent_seconds, last_accessed_at, completed_at.
6. **user_streaks**
   - Daily learning streaks and XP records.
   - Columns: user_id, date, lessons_completed, minutes_studied, xp.
7. **user_vocabulary_progress**
   - Vocabulary learning progress.
   - Columns: user_id, ocabulary_id, mastery_level, mastered, eview_count, last_reviewed_at, created_at.

## Constraints & Relations
- Primary keys established on all tables.
- Foreign keys from all progress/streak/srs tables linking user_id to users(id) with ON DELETE cascade.
- Unique constraints to prevent duplicate tracking for cards, badges, and emails.
